# 大宗 3.0 指标驱动交易平台 PRD

> 版本：V1.0  
> 日期：2026-05-12  
> 范围：基于现有交互页面、卖家工作台 PRD、核心场景推导、董事长会议纪要、一个月规划与市场研究院设计思路整理  
> 当前阶段：产品方案与原型评审阶段，尚未进入开发实施

---

## 1. 背景说明

### 1.1 业务背景

大宗 3.0 的建设目标不是复刻传统 B2B 商城，而是围绕工业品/大宗商品的真实交易逻辑，构建以“指标”为核心的交易、沟通、撮合、履约与数据沉淀平台。

现有沟通中已明确：

- 工业品交易的本质不是买卖商品名称，而是买卖一组可验证、可比较、可协商的指标。
- 买家关注的是热值、硫分、水分、灰分、固定碳、库存、吨位、交付条件、历史成交价格等结构化信息。
- 卖家痛点不是“没有货”，而是货品优势、指标价值、定价依据和交付能力表达不清。
- 平台未来要从物流服务提供者升级为区域供应链整合者、商品控权者与智能决策赋能者。
- 当平台逐步锁定区域核心品类供给比例后，可形成价格影响力、供应链组织能力和未来自营基础。

### 1.2 当前问题

| 问题 | 业务表现 | 影响 |
|---|---|---|
| 商品表达不标准 | 卖家以商品名、图片、口头描述为主，指标价值没有被突出 | 买家难以快速判断是否匹配需求 |
| 价格依据不清晰 | 报价缺少同类指标成交区间、库存、吨位、交付条件支撑 | 容易陷入线下议价，平台无法沉淀价格体系 |
| 沟通分散 | 买卖双方依赖电话、微信等线下沟通 | 平台无法沉淀需求、议价、指标调整等关键数据 |
| 交易链路断点多 | 商品发布、询价、议价、订单、合同、物流、资金分散 | 卖家不知道下一步该做什么，运营难以介入 |
| 平台专业能力不足 | 交易数据未转化为指标知识、应用建议和价格参考 | 平台容易停留在信息撮合层，难形成护城河 |

### 1.3 现有限制

- 当前已有页面以卖家工作台、后台 Dashboard、核心流程说明为主，买家侧链路仍需补齐。
- 市场研究院/应用实验室已有概念方向，但尚未形成完整数据模型和运营机制。
- IM 能力需要从“普通聊天”升级为“指标结构化沟通”，不能只做消息收发。
- 金融、碳足迹、平台自营等能力属于后续演进能力，第一阶段不宜做重。

## 2. 目标定义

### 2.1 业务目标

| 目标 | 说明 |
|---|---|
| 从商品中心升级为指标中心 | 所有展示、筛选、比价、沟通、议价围绕指标展开 |
| 提升货主上平台意愿 | 帮助卖家把货讲清楚、优势讲明白、定价有依据 |
| 提升买家采购决策效率 | 买家可按指标筛选、对比、沟通、询价和下单 |
| 沉淀平台数据资产 | 将指标咨询、议价、成交价、库存、吨位、应用场景沉淀为平台能力 |
| 支撑供应链控货权 | 通过交易和数据逐步掌握区域核心品类供需与价格参考 |

### 2.2 运营目标

- 让卖家每天进入工作台后能看到：当前卖哪件货、卡在哪、为什么卡、下一步点哪里。
- 让买家从“看商品”转为“看指标、比指标、聊指标、买指标”。
- 让平台运营能介入商品审核、表达优化、异常订单、沟通协同与风险处置。
- 让研究院/实验室逐步沉淀高频指标、常见需求、应用建议、价格区间和组合规律。

### 2.3 可量化结果

| 指标 | 目标口径 |
|---|---|
| 商品指标完整率 | 已发布商品核心指标完整率达到 90% 以上 |
| 买家咨询转结构化率 | 指标咨询、报价、议价中结构化卡片占比达到 70% 以上 |
| 卖家响应效率 | 待回复咨询平均响应时长下降 |
| 交易推进效率 | 从询价到订单确认的平均节点耗时下降 |
| 数据沉淀规模 | 高频指标、相近指标价格参考、常见调整需求形成可查询数据 |

## 3. 用户角色

| 角色 | 职责 | 权限 | 核心关注点 | 操作边界 |
|---|---|---|---|---|
| 卖家/货主 | 发布商品、维护指标、报价议价、确认订单、签合同、发货 | 商品管理、报价、合同、物流、资金查看 | 更快卖货、价格合理、库存可控、回款及时 | 只能管理本企业商品、订单、资金与会话 |
| 买家/采购方 | 浏览货源、筛选指标、发起咨询、议价、下单 | 浏览、收藏、对比、询价、下单、合同确认 | 快速找到合适指标货源，降低采购风险 | 只能查看授权范围内商品与自身交易数据 |
| 平台运营 | 商品审核、表达优化、交易协同、异常处理 | 审核、运营介入、规则配置、数据查看 | 提升交易转化，降低流程卡点 | 不能绕过审批直接修改核心交易结果 |
| 承运方/物流服务 | 承接运输、反馈运单、上传回单 | 运单处理、状态更新、异常反馈 | 履约清晰、运输可追踪 | 仅处理被分配或授权的物流单 |
| 金融方/资金服务 | 授信、融资、放款、回款跟踪 | 金融审批、额度查看、风控记录 | 控制资金风险，提升交易效率 | 不直接修改交易订单核心字段 |
| 平台管理员 | 账户、权限、配置、审计、风控管理 | 全局配置、RBAC、审计、租户管理 | 系统稳定、合规、可追溯 | 高危操作需审批与日志留痕 |
| AI/专家助手 | 指标建议、标题优化、价格参考解释、需求归纳 | 仅建议、归纳、辅助生成 | 提升专业表达与匹配效率 | 不可绕过人工确认，不可直接覆盖核心业务数据 |

## 4. 业务流程

### 4.1 主流程：指标驱动交易闭环

| 步骤 | 发起方 | 处理方 | 状态变化 | 说明 |
|---|---|---|---|---|
| 1. 商品录入 | 卖家 | 卖家 | 草稿 | 录入商品基础信息、指标、库存、价格、交付条件 |
| 2. 提交审核 | 卖家 | 平台运营 | 待审核 | 校验指标完整性、材料、价格区间、企业资质 |
| 3. 表达优化 | 平台/AI | 卖家确认 | 待优化/已优化 | 提示高价值指标、标题、摘要、缺失信息 |
| 4. 商品上架 | 平台/系统 | 卖家 | 已上架 | 买家可搜索、筛选、对比、咨询 |
| 5. 买家筛选 | 买家 | 系统 | 浏览中 | 按指标、库存、吨位、价格、交付地筛选 |
| 6. 指标沟通 | 买家 | 卖家 | 咨询中 | 围绕具体指标发问，可生成结构化咨询卡 |
| 7. 报价议价 | 卖家/买家 | 双方 | 议价中 | 价格、吨位、指标可调范围、交付条件协商 |
| 8. 订单确认 | 买家/卖家 | 双方/平台 | 待确认/已确认 | 固化最终指标、吨位、单价、交期、付款方式 |
| 9. 合同签署 | 双方 | 平台/电子签 | 待签署/已签署 | 合同与订单、报价版本、指标数据关联 |
| 10. 物流履约 | 卖家/承运方 | 承运方 | 待发货/运输中/已签收 | 平台物流承接或记录外部物流 |
| 11. 资金结算 | 买家/金融方 | 平台/银行 | 待支付/已支付/已结算 | 保证金、尾款、授信、回款跟踪 |
| 12. 交易完成 | 系统 | 双方 | 已完成 | 沉淀成交价格、指标、库存、需求与评价 |

### 4.2 审批流程

| 审批对象 | 触发条件 | 审批人 | 审批结果 |
|---|---|---|---|
| 商品发布 | 新商品提交、关键指标变更、材料变更 | 平台运营 | 通过/驳回/要求补充 |
| 价格异常 | 报价高于或低于相近指标区间阈值 | 平台运营/风控 | 放行/提示风险/限制发布 |
| 合同签署 | 订单进入合同阶段 | 双方企业授权人 | 签署/拒签/退回修改 |
| 资金提现 | 卖家提现、保证金退回 | 财务/风控 | 通过/驳回 |
| 授信融资 | 买家或卖家发起金融服务 | 金融方/风控 | 通过/驳回/补充资料 |
| 异常售后 | 退货退款、质量争议、物流异常 | 平台客服/风控 | 介入/仲裁/关闭 |

### 4.3 异常流程

| 异常场景 | 处理方式 |
|---|---|
| 指标材料缺失 | 商品进入待补充状态，不允许正式上架或限制曝光 |
| 价格超出参考区间 | 系统提示原因，必要时触发运营审核 |
| 库存不足 | 工作台待办提醒，商品可售状态调整为库存不足 |
| 买家长时间未确认 | 超时提醒，订单进入待跟进状态 |
| 卖家长时间未回复 | 沟通中心标记待回复，运营可介入提醒 |
| 合同拒签 | 回退至订单确认或议价阶段，保留历史版本 |
| 物流异常 | 运单进入异常状态，承运方/平台介入 |
| 退款退货 | 进入售后流程，冻结相关资金并记录原因 |

### 4.4 回滚流程

| 回滚对象 | 回滚逻辑 |
|---|---|
| 商品发布 | 已发布商品可下架并回到待编辑状态，保留历史版本 |
| 指标修改 | 关键指标修改需生成新版本，历史订单使用成交时版本 |
| 报价修改 | 报价卡保留版本记录，订单仅引用最终确认版本 |
| 订单确认 | 未签合同前可撤回至议价中；已签合同后需走变更/作废流程 |
| 合同签署 | 已签合同不可直接覆盖，只能补充协议或作废重签 |
| 物流履约 | 已发运状态不可简单回滚，只能走异常/取消/改派流程 |
| 资金结算 | 已支付资金需走退款、冲正或财务审批流程 |

## 5. 功能需求

### 5.1 卖家工作台

**功能目标：** 让卖家在一个页面内完成商品经营、待办处理、指标维护、沟通响应、订单推进、物流与合同查看。

| 模块 | 功能需求 | 业务规则 | 异常处理 |
|---|---|---|---|
| 顶部导航 | 工作台、大宗商品、拍卖中心、企业信息、经营分、消息入口 | 当前企业身份决定数据可见范围 | 无企业权限时禁止进入工作台 |
| 待办卡片 | 咨询待办、订单待办、合同待办、库存待办、售后待办 | 点击后定位到对应模块或沟通中心 | 数据加载失败显示重试 |
| 经营数据总览 | 在售商品、成交金额、订单量、买家数、访客、查看、评价 | 支持年/月/周切换 | 无数据展示空状态 |
| 当前主推商品 | 商品图片、名称、价格、库存、产地、商品 ID、状态 | 主推商品由卖家选择或系统推荐 | 商品下架时提示切换 |
| 指标维护 | 发热量、硫分、水分、灰分、挥发分、固定碳等 | 指标按品类模板配置，支持新增指标 | 超出规则范围需提示或审核 |
| 价格与交易条件 | 高低限价、起售量、库存、交易方式、交付方式、有效期 | 价格需与库存、吨位、有效期绑定 | 过期价格需重新确认 |
| 同类指标价格参考 | 匹配度、近 7 天成交区间、均价、当前报价位置 | 同类指标默认不超过 5% 浮动，预留 5%-10% 可调区间 | 样本不足时展示数据不足说明 |
| 指标经营建议 | 高价值指标、缺失信息、溢价依据、买家关注点 | AI/系统仅提供建议，卖家确认后生效 | 建议内容需留痕 |
| 成交进度 | 询价、报价、订单确认、合同、发货、完成、售后 | 节点与订单状态联动 | 异常节点标红并可查看原因 |
| 合同管理 | 上传合同、待签署、已签署 | 合同需关联订单与双方主体 | 文件格式或权限异常提示 |
| 物流服务 | 待发货、运输中、已签收、前往发货 | 运单关联订单、商品、吨位 | 物流异常进入异常处理 |
| 可用余额 | 可用、冻结、保证金、应收、交易记录 | 资金数据需权限控制 | 资金异常需风控介入 |

### 5.2 买家商品列表页

**功能目标：** 让买家按指标快速筛选货源，而不是按商品名称浏览。

| 功能点 | 需求说明 |
|---|---|
| 关键词/品类搜索 | 支持商品名、品类、产地、供应商搜索 |
| 指标筛选 | 支持按核心指标区间筛选，如热值、硫分、水分、灰分 |
| 库存/吨位筛选 | 支持按可售吨位、起售量筛选 |
| 价格筛选 | 支持按当前报价、近 7 天成交参考筛选 |
| 匹配度排序 | 按目标指标匹配度、价格、库存、更新时间排序 |
| 货源卡片 | 展示指标摘要、库存、价格、交付地、物流/金融标签 |
| 快捷动作 | 收藏、加入对比、立即沟通、查看详情 |

### 5.3 商品详情页

**功能目标：** 把指标、价格、库存、交付条件和沟通入口上移，让买家快速判断是否可交易。

| 区域 | 功能需求 |
|---|---|
| 商品摘要 | 商品名、品类、产地、供应商、状态 |
| 核心指标 | 以指标卡形式展示核心数值、单位、可调状态、材料依据 |
| 价格与库存 | 当前报价、近 7 天相近指标成交区间、库存、起售量 |
| 交付条件 | 提货地、交付方式、付款方式、发货周期 |
| 材料证明 | 检测报告、质检文件、合同样本、其他附件 |
| IM 入口 | 每个关键指标可直接发起咨询 |
| 转交易动作 | 询价、议价、下单、加入对比 |

### 5.4 企业沟通中心 / IM 交易能力

**功能目标：** 将买卖双方围绕指标的咨询、报价、议价和订单推进纳入平台沉淀。

| 模块 | 功能需求 | 业务规则 |
|---|---|---|
| 企业会话列表 | 按企业聚合会话，展示企业名、未读、状态、最近摘要 | 不按零散消息拆分，按企业和交易线索聚合 |
| 会话筛选 | 待回复、议价中、待确认、已完成 | 状态由最新业务卡片决定 |
| 指标咨询卡 | 买家针对某个指标提问，如“硫分能否降低” | 必须关联商品、指标、当前值 |
| 报价卡 | 卖家发起报价，包含商品、吨位、单价、有效期 | 修改报价生成新版本 |
| 议价修改卡 | 买家修改价格、吨位、指标要求、交期 | 卖家可接受、拒绝、重新报价 |
| 订单推进卡 | 报价确认后转订单、转合同 | 转订单前需确认关键字段 |
| 历史留痕 | 保留消息、报价、议价、订单推进记录 | 作为审计与纠纷依据 |
| 平台可视 | 运营可查看授权范围内沟通摘要和异常 | 敏感内容按权限脱敏 |

### 5.5 指标对比页

**功能目标：** 让买家基于指标差异、价格区间和库存做选择。

| 功能点 | 需求说明 |
|---|---|
| 对比池 | 支持添加/移除多个货源 |
| 指标容差 | 默认支持 5% 内同类指标对比，预留 5%-10% 可调区间 |
| 差异高亮 | 高亮优势指标、劣势指标、价格差异 |
| 成交价参考 | 展示相近指标历史成交区间 |
| 推荐结果 | 推荐最接近目标指标或性价比更优货源 |
| 快捷动作 | 发起沟通、询价、转需求实验 |

### 5.6 订单确认页

**功能目标：** 将沟通结果固化为可履约、可签约、可结算的订单。

| 字段 | 是否必填 | 规则 |
|---|---|---|
| 商品 | 是 | 必须为可交易状态 |
| 指标版本 | 是 | 锁定成交时指标版本 |
| 吨位/数量 | 是 | 不得超过可售库存 |
| 单价/总价 | 是 | 与报价版本一致或重新确认 |
| 交付方式 | 是 | 平台物流/买家自提/其他 |
| 提货/收货信息 | 是 | 完整地址与联系人 |
| 付款方式 | 是 | 预付、尾款、授信等 |
| 合同主体 | 是 | 买卖双方企业资质需有效 |
| 发票/税费 | 视业务 | 按品类与合同要求配置 |

### 5.7 拍卖管理能力

**功能目标：** 支持部分大宗商品以拍卖方式成交，突出标的指标、吨位、库存与价格规则。

| 功能点 | 需求说明 |
|---|---|
| 拍卖发布 | 选择商品、指标、库存、起拍价、保留价、加价幅度 |
| 前置约束 | 可配置买家数量、保证金金额等启动条件 |
| 买家准入 | 企业资质、保证金、权限校验 |
| 出价记录 | 保留出价时间、企业、价格、状态 |
| 自动签约价 | 达到规则条件后生成成交价 |
| 流拍处理 | 未达到条件则流拍，可重新发布 |

### 5.8 市场研究院 / 应用实验室

**功能目标：** 沉淀指标讨论、需求趋势、应用场景和价格参考，形成平台专业壁垒。

| 能力区 | 功能需求 |
|---|---|
| 高频指标讨论 | 展示近期高频被问指标、常见问题、常见调整方向 |
| 应用场景建议 | 根据指标组合推荐适用行业、工艺或使用场景 |
| 指标需求实验 | 买家选择指标、目标值、容差范围，生成结构化需求 |
| 相近货源匹配 | 根据需求组合推荐最接近货源 |
| 研究结论输出 | 输出最影响成交指标、价格区间、需求组合、优势卖家 |
| 数据反哺 | 将研究结论回流到卖家经营建议和买家筛选推荐 |

### 5.9 碳足迹 / 溯源概念能力

**阶段定位：** 第一阶段仅做字段预研和展示位置预留，不做完整碳核算系统。

| 功能点 | 说明 |
|---|---|
| 碳足迹记录 | 记录生产、加工、仓储、运输等环节的碳相关信息 |
| 企业自报 | 企业可提交节能、减排、碳指标说明 |
| 第三方验证 | 后续支持第三方材料上传和审核 |
| 商品展示 | 在商品详情和研究院中预留碳足迹信息展示 |

## 6. 权限设计

### 6.1 RBAC 权限模型

| 权限域 | 权限项 |
|---|---|
| 商品权限 | 查看、创建、编辑、提交审核、下架、删除草稿 |
| 指标权限 | 查看、编辑、新增、标记高价值、查看历史版本 |
| 交易权限 | 询价、报价、议价、确认订单、取消订单 |
| 合同权限 | 上传、预览、签署、作废、查看历史 |
| 物流权限 | 发起物流、查看运单、更新状态、异常反馈 |
| 资金权限 | 查看余额、查看流水、充值、提现、保证金处理 |
| 沟通权限 | 查看会话、回复、发报价、转订单、运营介入 |
| 运营权限 | 商品审核、表达优化、异常处理、规则配置 |
| 管理权限 | 用户、角色、部门、租户、审计、系统配置 |

### 6.2 租户隔离

- 企业用户只能访问本企业商品、订单、合同、资金、会话。
- 平台运营按组织权限查看分配范围内数据。
- 承运方仅可查看被分配运单及必要交易信息。
- 金融方仅可查看被授权的授信、合同、订单和风控材料。

### 6.3 部门数据可见范围

| 范围 | 说明 |
|---|---|
| 个人 | 仅本人创建或负责的数据 |
| 部门 | 本部门商品、订单、沟通与任务 |
| 企业 | 本企业全部授权数据 |
| 平台 | 平台运营授权范围内全局数据 |

### 6.4 审批权限

- 商品关键字段变更、价格异常、合同作废、资金提现、售后退款需配置审批流。
- AI 生成建议、指标优化建议、价格建议均需人工确认后生效。
- 高危操作必须记录操作人、审批人、时间、原因和前后变化。

## 9. 架构影响分析

### 9.1 影响模块

| 模块 | 影响 |
|---|---|
| 商品中心 | 从商品字段扩展为商品 + 指标模板 + 指标版本 |
| 交易中心 | 报价、议价、订单需绑定指标版本和报价版本 |
| IM/沟通中心 | 从普通消息升级为结构化业务卡片 |
| 合同中心 | 合同需关联订单、报价版本、指标版本 |
| 库存中心 | 需支持库存锁定、释放、超卖校验 |
| 物流中心 | 运单需关联订单、吨位、发运状态 |
| 资金中心 | 保证金、冻结金额、应收、提现、授信需统一建模 |
| 运营后台 | 商品审核、异常处理、规则配置、审计查看 |
| 数据研究中心 | 沉淀指标讨论、价格参考、应用场景、需求组合 |
| AI 能力 | 仅提供建议、摘要、归纳，不直接修改核心数据 |

### 9.2 API First 建议

建议按服务边界设计 API：

- 商品与指标服务：商品、指标模板、指标版本、材料附件
- 价格与库存服务：报价、成交价、库存、锁定库存
- 沟通服务：会话、消息、结构化卡片、未读状态
- 交易服务：询价、议价、订单、合同流转
- 履约服务：物流、签收、异常、回单
- 资金服务：余额、保证金、冻结、结算、提现
- 研究服务：高频指标、需求组合、价格区间、应用建议
- 审计服务：操作日志、审批日志、风险事件

### 9.3 数据迁移风险

| 风险 | 说明 | 建议 |
|---|---|---|
| 原商品数据缺指标 | 历史商品可能只有文本描述 | 建立品类指标模板，分批补录 |
| 指标口径不统一 | 不同卖家单位、名称、范围不一致 | 建立指标字典和单位换算规则 |
| 历史报价无版本 | 旧报价无法追溯对应指标 | 新链路强制报价版本化 |
| 沟通数据非结构化 | 普通聊天难以沉淀研究数据 | 新增结构化卡片和指标标注 |

### 9.4 回滚方案

- 商品指标版本化，允许恢复到历史版本。
- 报价版本化，订单仅引用最终确认版本。
- 新 IM 卡片能力可与普通文本消息并行，避免一次性替换。
- 研究院数据先做只读汇总，不影响交易主流程。
- AI 建议以草稿/建议状态存在，人工确认前不写入核心交易数据。

## 10. AI 产品边界

| 能力 | 可做 | 禁止 |
|---|---|---|
| 指标表达优化 | 生成标题、摘要、卖点建议 | 自动发布商品 |
| 价格参考解释 | 解释当前报价相对市场区间的位置 | 自动改价 |
| 沟通摘要 | 归纳买家需求、待办、议价变化 | 替用户承诺交易条件 |
| 研究院分析 | 统计高频指标、需求组合、趋势 | 直接给出强制经营决策 |
| 风险提示 | 提示价格异常、材料缺失、库存风险 | 绕过审批放行 |

AI 输出必须满足：

- 可查看原始依据。
- 可被人工编辑、确认、驳回。
- 核心业务字段变更必须有人负责。
- 所有 AI 建议与采纳结果需要留痕。

|---|---|

|---|---|

| 审计 | 关键沟通和业务卡片可追溯 |

### 11.4 研究院/实验室

| 验收项 | 标准 |
|---|---|
| 高频指标 | 可展示近期高频讨论指标 |
| 应用建议 | 可展示指标组合与应用场景建议 |
| 需求实验 | 可选择指标、目标值、容差范围生成需求 |
| 数据反哺 | 研究结论可回流到经营建议或价格参考 |

## 12. 分阶段实施建议

### 阶段一：MVP，打通指标交易主链路

范围：

- 卖家工作台 2.0
- 商品发布与指标维护
- 买家列表与详情页
- 企业沟通中心基础版

- 同类指标价格参考基础规则

目标：

范围：

- 合同管理
- 物流履约
- 资金/保证金
- 拍卖管理
- 售后与异常处理
- 运营后台介入机制

目标：

- 让平台从信息撮合进入交易履约闭环。

### 阶段三：平台专业能力建设

范围：

- 市场研究院/应用实验室
- 高频指标讨论
- 应用场景建议
- 指标需求实验
- AI 经营建议

目标：

- 将交易数据沉淀为平台知识和专业壁垒。

### 阶段四：供应链与金融扩展

范围：

- 授信融资
- 仓单/应收账款支持

- 区域商品控权
- 平台自营/代工模式

目标：

- 支撑平台从交易工具升级为供应链中枢。

## 13. 项目交付风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 指标体系不统一 | 筛选、比价、研究院无法稳定运行 | 优先建设品类指标模板与指标字典 |
| IM 变成普通聊天 | 无法沉淀交易数据 | 必须设计结构化卡片和指标标注 |
| 价格参考样本不足 | 参考价值不稳定 | 样本不足时显示置信度或数据不足 |
| 过早做研究院重功能 | 分散主链路交付 | 第一阶段只做概念原型和轻量数据汇总 |
| 交易流程审批不足 | 合同、资金、售后风险高 | 审批流、权限、审计必须随主链路同步设计 |
| AI 越权 | 造成错误报价或错误数据覆盖 | AI 仅建议，人工确认后生效 |
| 库存并发冲突 | 超卖、履约失败 | 订单确认阶段必须锁定库存 |

#### QA Testing Input

| 类型 | 测试点 |
|---|---|
| Acceptance criteria | 可查看高频指标，可生成需求实验，可匹配相近货源 |
| Positive test cases | 选择指标生成需求成功；按容差匹配货源成功；点击货源发起沟通 |
| Negative test cases | 未选指标生成失败；样本不足不展示确定性价格；无权限看敏感价格 |
| Permission test cases | 买家、卖家、运营看到的数据范围不同 |
| Workflow test cases | 研究院首页 -> 指标详情 -> 需求实验 -> 匹配货源 -> 沟通 |
| Boundary test cases | 容差 5%、容差 10%、目标值上下限、需求吨位极小值 |
| Exception test cases | 统计接口失败、匹配结果为空、保存实验失败 |
| Regression test points | 商品指标变更后研究匹配、沟通中心需求卡、买家列表筛选逻辑 |

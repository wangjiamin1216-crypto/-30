# 买家议价沟通场景协议

## 1. 协议目标

本协议定义买家从指标商品列表页、指标商品详情页发起询价/议价后，买卖双方围绕指标商品进行表单式沟通、指标确认、价格协商、交易意向推进和订单成交发起的业务规则。

本协议重点解决：

- 买家如何从商品列表页和商品详情页发起询价、议价。
- 买家如何填写期望价格、期望调整指标参数、采购量、交货地、备注等结构化信息。
- 卖家如何接收议价、回复议价、修改议价方案、调整可协商指标参数。
- 买卖双方如何保留即时聊天与结构化议价表单记录。
- 议价如何形成状态流转。
- 议价成功、拒绝、失效、撤回等状态如何处理。
- 卖家如何基于已确认议价结果发起订单成交。
- MVP 阶段如何在即时聊天中嵌入表单式询价、议价能力。

本协议不定义：

- 卖家指标商品主状态机。
- 库存状态机。
- 订单完整状态机。
- 合同、物流、履约、金融完整流程。
- UI 视觉设计。
- 代码实现。

---

## 2. 场景边界

### 2.1 与指标商品的关系

议价沟通必须基于一个已上架指标商品发起。

| 关系 | 规则 |
| --- | --- |
| 指标商品是议价对象 | 议价必须关联指标商品 ID |
| 已上架是准入状态 | 只有 `当前状态 = 已上架` 且允许询价/议价时，买家才能发起新的询价或议价 |
| 指标商品字段只读 | 买家不得修改指标商品字段 |
| 卖家可调整议价方案 | 卖家可在议价中提出调整后的价格、吨位、交付条件或可协商指标参数 |
| 修改指标商品主字段需走原规则 | 如卖家要修改已上架商品的核心指标、指标值、指标容差等主字段，必须遵循卖家指标商品字段协议和审核规则 |

### 2.2 与即时聊天的关系

即时聊天是议价沟通的承载容器，不是普通聊天工具。

MVP 阶段要求：

- 企业沟通中心中必须支持普通文本消息。
- 企业沟通中心中必须支持表单式询价卡。
- 企业沟通中心中必须支持表单式议价卡。
- 表单卡片必须结构化记录价格、指标、吨位、交付和备注。
- 文本聊天不得替代表单式议价记录。
- 关键议价动作必须生成可追溯记录。

### 2.3 与订单成交的关系

议价成功后，卖家可以基于议价结果发起订单成交。

说明：

- 本协议只定义“卖家发起订单成交入口”和订单创建前置条件。
- 本协议不定义订单完整状态机。
- 订单创建后由订单业务域承接。
- 订单不得反向修改议价历史记录。

## 3. 核心角色

| 角色 | 角色目标 | 主要行为 |
| --- | --- | --- |
| 买家 | 围绕指标商品提出采购需求、价格诉求和指标调整诉求 | 发起询价、发起议价、修改议价诉求、撤回议价、确认卖家方案 |
| 卖家 | 接收买家议价诉求，判断是否可成交，并给出回复方案 | 接收议价、接受议价、拒绝议价、修改议价、调整指标方案、发起订单成交 |
| 平台 | 提供状态校验、行为留痕、权限控制和异常处理 | 校验商品状态、记录沟通日志、记录议价版本、处理失效和异常 |

---

## 4. 核心业务对象

### 4.1 议价沟通单

议价沟通单是买卖双方围绕单个指标商品进行询价、议价和交易意向确认的核心对象。

| 字段 | 说明 |
| --- | --- |
| 议价沟通单 ID | 唯一标识 |
| 指标商品 ID | 关联的指标商品 |
| 指标商品状态版本号 | 发起时读取的指标商品版本，用于并发校验 |
| 买家企业 ID | 发起询价/议价的买方企业 |
| 卖家企业 ID | 接收询价/议价的卖方企业 |
| 会话 ID | 所属企业沟通会话 |
| 来源页面 | 商品列表页、商品详情页、企业沟通中心 |
| 单据类型 | 询价、议价 |
| 当前状态 | 议价沟通单自身状态 |
| 当前版本号 | 每次修改议价内容时递增 |
| 发起人 | 买家用户 ID |
| 当前处理方 | 买家或卖家 |
| 创建时间 | 首次发起时间 |
| 最近更新时间 | 最近一次修改或回复时间 |
| 失效时间 | 超过该时间未处理则失效 |

### 4.2 买家询价/议价表单

买家询价/议价表单用于结构化表达买家诉求。

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 采购量 | 是 | 买家期望采购吨位 |
| 期望价格 | 议价必填，询价可选 | 买家期望成交价格 |
| 价格单位 | 是 | 例如元/吨 |
| 期望调整指标参数 | 否 | 买家希望调整或确认的指标项 |
| 指标容差诉求 | 否 | 对核心指标上下限的诉求 |
| 交货地 | 是 | 买家期望交货地点或区域 |
| 交付方式 | 否 | 买家期望火运、汽运、到厂、自提等方式 |
| 期望交付时间 | 否 | 买家期望交付周期 |
| 付款或结算备注 | 否 | 结算方式、账期等补充诉求 |
| 检测/扣罚备注 | 否 | 检测报告、复检、指标扣罚规则 |
| 其他备注 | 否 | 买家补充说明 |

### 4.3 指标调整项

指标调整项用于记录买家期望调整或卖家可接受调整的指标参数。

| 字段 | 说明 |
| --- | --- |
| 指标名称 | 例如收到基低位发热量、全硫分、全水分、灰分 |
| 原指标值 | 来自卖家发布的指标商品字段 |
| 原指标单位 | 来自卖家发布的指标商品字段 |
| 原容差下限 | 来自卖家发布的指标商品字段 |
| 原容差上限 | 来自卖家发布的指标商品字段 |
| 买家期望值 | 买家提出的目标值 |
| 买家期望容差下限 | 买家提出的最低可接受边界 |
| 买家期望容差上限 | 买家提出的最高可接受边界 |
| 卖家回复值 | 卖家在议价中给出的可接受值 |
| 卖家回复容差 | 卖家在议价中给出的可接受容差 |
| 调整说明 | 双方对指标调整原因、检测口径的说明 |

说明：

- 指标调整项是议价沟通单内的协商数据。
- 指标调整项不直接修改指标商品主字段。
- 如卖家确认要长期修改商品指标，应回到卖家侧指标商品编辑和审核流程。

### 4.4 卖家回复方案

卖家回复方案用于记录卖家对买家询价/议价的处理结果。

| 字段 | 说明 |
| --- | --- |
| 回复方案 ID | 唯一标识 |
| 议价沟通单 ID | 关联议价沟通单 |
| 回复类型 | 接受、拒绝、修改后报价、补充说明 |
| 卖家报价 | 卖家本轮给出的价格 |
| 价格单位 | 例如元/吨 |
| 可承接采购量 | 卖家可承接吨位 |
| 可承接交货地 | 卖家可承接交货地点 |
| 可承接交付方式 | 卖家可承接交付方式 |
| 可接受指标调整 | 卖家可接受或建议的指标参数 |
| 回复备注 | 卖家补充说明 |
| 有效期 | 本轮回复方案有效截止时间 |
| 回复人 | 卖家用户 ID |
| 回复时间 | 回复发生时间 |

### 4.5 沟通记录

沟通记录用于保留即时聊天和表单式议价的完整过程。

| 字段 | 说明 |
| --- | --- |
| 消息 ID | 唯一标识 |
| 会话 ID | 所属企业沟通会话 |
| 议价沟通单 ID | 如消息关联议价单则记录 |
| 消息类型 | 文本、询价卡、议价卡、卖家回复卡、系统状态卡、订单发起卡 |
| 发送方企业 ID | 买家或卖家企业 |
| 发送方用户 ID | 操作用户 |
| 消息内容 | 文本内容或表单摘要 |
| 结构化数据快照 | 表单字段快照 |
| 发送时间 | 消息发送时间 |
| 是否可追溯 | 核心动作消息必须可追溯 |

## 5. 发起入口

### 5.1 从商品列表页发起

| 入口 | 触发条件 | 传递对象 |
| --- | --- | --- |
| 发起询价 | 指标商品已上架且允许询价 | 指标商品 ID、买家企业 ID、卖家企业 ID、来源页面、状态版本号 |
| 发起议价 | 指标商品已上架且允许议价 | 指标商品 ID、买家企业 ID、卖家企业 ID、来源页面、状态版本号 |

列表页发起时：

- 默认带入列表筛选条件作为买家采购意图参考。
- 默认带入商品核心指标摘要。
- 默认带入报价、价格单位、可售吨位、最小起售数量、交付区域。
- 进入企业沟通中心后生成询价卡或议价卡草稿。

### 5.2 从商品详情页发起

| 入口 | 触发条件 | 传递对象 |
| --- | --- | --- |
| 发起询价 | 当前商品已上架且允许询价 | 指标商品 ID、买家企业 ID、卖家企业 ID、详情页来源、状态版本号 |
| 发起议价 | 当前商品已上架且允许议价 | 指标商品 ID、买家企业 ID、卖家企业 ID、议价诉求草稿、状态版本号 |

详情页发起时：

- 可带入买家在详情页关注的指标项。
- 可带入决策增强模块生成的议价参考信息。
- 可带入买家目标采购量、目标交货地、期望价格。
- 可带入买家对指标容差、检测报告、扣罚规则的备注。

### 5.3 发起前置校验

| 校验项 | 规则 |
| --- | --- |
| 指标商品状态 | 必须为已上架 |
| 询价/议价入口 | 必须允许询价或允许议价 |
| 状态版本号 | 必须与服务端最新版本一致 |
| 价格有效期 | 如价格已失效，必须提示重新确认价格 |
| 可售吨位 | 买家采购量不得超过可承诺范围，或需标记为需卖家确认 |
| 最小起售数量 | 买家采购量不得低于最小起售数量 |
| 买家权限 | 买家企业必须具备查看和发起沟通权限 |

## 6. 表单式询价/议价

### 6.1 询价表单

询价用于买家向卖家确认价格、吨位、交付和指标口径，价格不是必须字段。

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 采购量 | 是 | 买家预计采购吨位 |
| 交货地 | 是 | 买家期望交货地点 |
| 期望交付时间 | 否 | 计划交付周期 |
| 关注指标 | 否 | 买家希望确认的指标项 |
| 指标确认问题 | 否 | 对检测口径、容差、报告的提问 |
| 备注 | 否 | 其他说明 |

询价提交结果：

- 生成询价沟通单。
- 在企业沟通中心生成询价卡。
- 通知卖家处理。
- 不锁定价格。
- 不锁定库存。
- 不生成订单。

### 6.2 议价表单

议价用于买家对价格、指标、吨位、交付条件提出明确诉求。

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 采购量 | 是 | 买家期望采购吨位 |
| 期望价格 | 是 | 买家期望成交价格 |
| 价格单位 | 是 | 例如元/吨 |
| 期望调整指标参数 | 否 | 买家希望调整或确认的指标 |
| 指标容差诉求 | 否 | 买家希望接受的指标上下限 |
| 交货地 | 是 | 买家期望交货地 |
| 交付方式 | 否 | 买家期望交付方式 |
| 期望交付时间 | 否 | 买家希望交付日期或周期 |
| 检测/扣罚备注 | 否 | 对检测、复检、扣罚规则的要求 |
| 付款/结算备注 | 否 | 对付款和结算的说明 |
| 其他备注 | 否 | 补充说明 |

议价提交结果：

- 生成议价沟通单。
- 在企业沟通中心生成议价卡。
- 议价状态进入待卖家响应。
- 通知卖家处理。
- 不锁定库存。
- 不生成订单。

### 6.3 即时聊天中的表单卡片

MVP 阶段即时聊天必须支持以下卡片：

| 卡片 | 发送方 | 用途 |
| --- | --- | --- |
| 询价卡 | 买家 | 结构化提交采购量、交货地、指标确认问题 |
| 议价卡 | 买家 | 结构化提交期望价格、指标调整诉求、采购量、交货地 |
| 卖家回复卡 | 卖家 | 回复接受、拒绝或修改后报价 |
| 指标调整卡 | 买家或卖家 | 记录某一轮指标参数调整诉求 |
| 系统状态卡 | 系统 | 记录议价状态变化 |
| 订单发起卡 | 卖家 | 议价成功后发起订单成交入口 |

卡片规则：

- 卡片提交后必须固化为历史快照。
- 后续修改不得覆盖历史卡片，只能生成新版本卡片。
- 卡片必须可在会话中按时间顺序追溯。
- 文本消息可以补充说明，但不得替代表单卡片。

## 7. 议价状态流转

### 7.1 状态列表

议价状态是议价沟通单自身状态，不是指标商品状态。

| 状态 | 状态类型 | 业务含义 |
| --- | --- | --- |
| 草稿 | 初始状态 | 买家已打开询价/议价表单但尚未提交 |
| 待卖家响应 | 中间状态 | 买家已提交，等待卖家处理 |
| 卖家已修改 | 中间状态 | 卖家未接受原诉求，给出修改后的价格、指标或交付方案 |
| 待买家确认 | 中间状态 | 卖家修改方案后等待买家确认 |
| 议价成功 | 完成状态 | 双方确认价格、指标、吨位和交付条件 |
| 已拒绝 | 终止状态 | 卖家拒绝买家诉求或买家拒绝卖家方案 |
| 已撤回 | 终止状态 | 买家在卖家确认前主动撤回 |
| 已失效 | 终止状态 | 超过有效期或商品状态变化导致议价不可继续 |
| 已转订单 | 完成后承接状态 | 卖家基于议价成功结果发起订单成交 |

### 7.2 总体流转

```text
草稿
  -> 买家提交
  -> 待卖家响应

待卖家响应
  -> 卖家接受
  -> 议价成功

待卖家响应
  -> 卖家修改方案
  -> 卖家已修改
  -> 待买家确认
  -> 买家确认
  -> 议价成功

待买家确认
  -> 买家拒绝
  -> 已拒绝

待卖家响应
  -> 卖家拒绝
  -> 已拒绝

待卖家响应 / 卖家已修改 / 待买家确认
  -> 买家撤回
  -> 已撤回

待卖家响应 / 卖家已修改 / 待买家确认
  -> 超时 / 商品下架 / 入口关闭 / 价格过期且未重新确认
  -> 已失效

议价成功
  -> 卖家发起订单成交
  -> 已转订单
```

### 7.3 状态说明

#### 草稿

草稿表示买家正在填写询价或议价表单，但尚未提交给卖家。

规则：

- 只对买家自身可见。
- 不通知卖家。
- 不生成卖家待办。
- 可保存或放弃。

#### 待卖家响应

待卖家响应表示买家已正式提交询价或议价。

规则：

- 卖家可查看买家提交的表单卡。
- 卖家可接受、拒绝或修改方案。
- 买家可在卖家处理前撤回。
- 系统记录提交时间和有效期。

#### 卖家已修改

卖家已修改表示卖家对买家的价格、指标、吨位或交付诉求做出修改后回复。

规则：

- 卖家修改不得覆盖买家原始诉求。
- 卖家修改必须生成卖家回复卡。
- 修改内容必须结构化记录。
- 修改后进入待买家确认。

#### 待买家确认

待买家确认表示卖家已给出修改方案，等待买家确认是否接受。

规则：

- 买家可确认、拒绝或继续发起新一轮修改诉求。
- 如继续修改，应生成新版本议价卡。
- 超过有效期未确认则进入已失效。

#### 议价成功

议价成功表示双方已确认价格、采购量、指标口径和交付条件。

规则：

- 生成议价成功系统状态卡。
- 固化最终议价快照。
- 卖家可发起订单成交。
- 买家不可再修改该轮议价结果。
- 如需调整，应重新发起新议价。

#### 已拒绝

已拒绝表示卖家拒绝买家诉求，或买家拒绝卖家修改方案。

规则：

- 必须记录拒绝方、拒绝原因和拒绝时间。
- 已拒绝后不可继续编辑。
- 可基于同一指标商品重新发起新的询价或议价，前提是商品仍已上架且入口开放。

#### 已撤回

已撤回表示买家主动撤回已提交但尚未最终确认的议价。

规则：

- 只有买家可撤回自身发起的议价。
- 已议价成功、已拒绝、已失效、已转订单不可撤回。
- 撤回必须记录撤回原因和时间。

#### 已失效

已失效表示议价因超时、商品状态变化、价格有效期失效或入口关闭而不可继续。

规则：

- 已失效后不可继续编辑。
- 商品下架后不得继续基于该商品新增议价。
- 历史记录可查看。

#### 已转订单

已转订单表示卖家已基于议价成功结果发起订单成交。

规则：

- 只允许从议价成功进入。
- 生成订单发起卡。
- 订单后续由订单业务域承接。
- 已转订单后议价结果不可修改。

---

## 8. 卖家处理规则

### 8.1 卖家接收议价

卖家在企业沟通中心、卖家工作台待响应沟通消息中接收买家议价。

卖家接收后可执行：

- 查看买家询价/议价表单。
- 查看关联指标商品。
- 查看买家期望价格。
- 查看买家期望调整指标参数。
- 查看采购量、交货地、备注。
- 接受议价。
- 拒绝议价。
- 修改议价方案。
- 修改可协商指标参数。
- 发起订单成交。

### 8.2 卖家修改议价

卖家可以修改以下议价方案字段：

| 字段 | 说明 |
| --- | --- |
| 卖家回复价格 | 卖家给出的可接受价格 |
| 可承接采购量 | 卖家可承接吨位 |
| 可承接交货地 | 卖家可承接交付区域 |
| 可承接交付方式 | 卖家可承接运输或交付方式 |
| 可接受指标调整 | 卖家可接受的指标参数或容差 |
| 回复有效期 | 卖家本轮方案有效截止时间 |
| 回复备注 | 卖家补充说明 |

规则：

- 卖家修改议价只修改议价沟通单，不直接修改指标商品主字段。
- 卖家回复价格不得覆盖买家期望价格。
- 卖家调整指标参数不得覆盖原指标商品字段。
- 每次卖家修改必须生成新的回复版本。

### 8.3 卖家修改指标

卖家在议价沟通中可以提出“可协商指标方案”。

可协商指标方案包括：

- 对某一指标的可接受范围。
- 对某一指标的批次波动说明。
- 对某一指标的检测口径说明。
- 对某一指标不达标时的扣罚说明。
- 对买家期望指标无法满足的拒绝说明。

重要边界：

- 议价中的“修改指标”是修改本次议价方案中的指标参数，不是直接修改已上架指标商品主字段。
- 如卖家要长期修改商品核心指标、指标值、指标容差，应回到卖家侧指标商品编辑/审核流程。
- 议价成功后形成的是本次交易意向快照，不代表指标商品字段被永久修改。

### 8.4 卖家发起订单成交

卖家可在议价成功后发起订单成交。

前置条件：

- 议价状态为议价成功。
- 最终议价快照已生成。
- 指标商品仍允许进入交易承接。
- 买卖双方企业信息有效。
- 采购量、成交价格、交货地、交付方式、指标口径已确认。

订单发起时传递对象：

| 对象 | 说明 |
| --- | --- |
| 议价沟通单 ID | 订单来源 |
| 指标商品 ID | 订单关联商品 |
| 买家企业 ID | 采购方 |
| 卖家企业 ID | 供应方 |
| 最终成交价格 | 来自议价成功快照 |
| 成交采购量 | 来自议价成功快照 |
| 成交指标参数 | 来自议价成功快照 |
| 交货地 | 来自议价成功快照 |
| 交付方式 | 来自议价成功快照 |
| 备注和附加条款 | 来自议价成功快照 |

本协议不定义订单后续状态。

## 9. 双方沟通记录

### 9.1 记录范围

以下行为必须进入沟通记录：

- 买家提交询价。
- 买家提交议价。
- 买家修改议价诉求。
- 买家撤回议价。
- 卖家接受议价。
- 卖家拒绝议价。
- 卖家修改议价方案。
- 卖家提出可协商指标方案。
- 买家确认卖家方案。
- 买家拒绝卖家方案。
- 议价成功。
- 议价失效。
- 卖家发起订单成交。

### 9.2 记录形式

| 记录类型 | 说明 |
| --- | --- |
| 文本消息 | 双方自由沟通补充说明 |
| 表单卡片 | 询价、议价、卖家回复、指标调整等结构化内容 |
| 系统状态卡 | 状态变化的自动记录 |
| 操作日志 | 后台审计用操作记录 |

### 9.3 记录规则

- 表单卡片不得被覆盖，只能追加新版本。
- 状态变化必须生成系统状态卡。
- 文本消息不得修改表单字段。
- 关键行为必须记录操作人、企业、时间、原状态、新状态。
- 历史沟通记录在商品下架后仍可按权限查看。

## 10. 权限规则

| 行为 | 买家 | 卖家 | 平台 |
| --- | --- | --- | --- |
| 发起询价 | 可执行 | 不可替买家发起 | 可审计 |
| 发起议价 | 可执行 | 不可替买家发起 | 可审计 |
| 修改买家议价诉求 | 发起方可修改未终态诉求 | 不可修改买家原始诉求 | 可审计 |
| 接受议价 | 不可执行 | 可执行 | 可审计 |
| 拒绝议价 | 可拒绝卖家修改方案 | 可拒绝买家诉求 | 可审计 |
| 修改卖家方案 | 不可修改卖家方案 | 可执行 | 可审计 |
| 撤回议价 | 发起买家可撤回 | 不可撤回买家议价 | 可审计 |
| 发起订单成交 | 不可替卖家发起 | 议价成功后可发起 | 可审计 |
| 查看历史记录 | 仅查看本企业相关记录 | 仅查看本企业相关记录 | 按权限查看 |

## 11. 异常与风控

| 风险点 | 处理规则 |
| --- | --- |
| 商品已下架后继续议价 | 阻断新增议价，历史议价只读 |
| 状态版本过期 | 提交前校验指标商品状态版本号，过期则要求刷新 |
| 可售吨位不足 | 提交或卖家确认前校验可售吨位，不足则提示或阻断 |
| 价格有效期失效 | 议价前提示重新确认价格，必要时进入已失效 |
| 重复提交 | 同一买家、同一商品、同一会话内短时间重复提交需提示 |
| 越权操作 | 非本企业用户不得查看或操作议价单 |
| 卖家覆盖买家诉求 | 禁止覆盖，只能追加卖家回复版本 |
| 买家覆盖卖家回复 | 禁止覆盖，只能确认、拒绝或发起新一轮议价 |
| 终态后继续修改 | 已拒绝、已撤回、已失效、已转订单不可继续修改 |
| 文本绕过表单 | 关键议价内容必须以表单卡片固化 |

## 12. 状态日志要求

每次议价状态变化必须记录状态日志。

状态日志字段：

- 议价沟通单 ID。
- 指标商品 ID。
- 买家企业 ID。
- 卖家企业 ID。
- 操作人。
- 操作人角色。
- 操作时间。
- 原状态。
- 新状态。
- 操作类型。
- 操作原因。
- 当前版本号。
- 关联消息 ID。
- 关联表单卡片 ID。
- 备注。

必须记录日志的状态变化：

| 状态变化 | 日志要求 |
| --- | --- |
| 草稿 -> 待卖家响应 | 记录买家提交内容、来源页面、商品版本号 |
| 待卖家响应 -> 议价成功 | 记录卖家接受时间、最终价格、采购量、交付条件 |
| 待卖家响应 -> 卖家已修改 | 记录卖家修改内容和回复版本 |
| 卖家已修改 -> 待买家确认 | 记录等待买家确认的方案快照 |
| 待买家确认 -> 议价成功 | 记录买家确认时间和最终方案 |
| 待卖家响应/待买家确认 -> 已拒绝 | 记录拒绝方和拒绝原因 |
| 待卖家响应/待买家确认 -> 已撤回 | 记录撤回人和撤回原因 |
| 待卖家响应/待买家确认 -> 已失效 | 记录失效原因和触发来源 |
| 议价成功 -> 已转订单 | 记录订单发起人、订单来源和最终快照 |

## 14. MVP边界

### 14.1 MVP 必须支持

- 买家从商品列表页发起询价。
- 买家从商品列表页发起议价。
- 买家从商品详情页发起询价。
- 买家从商品详情页发起议价。
- 买家填写采购量、期望价格、期望调整指标参数、交货地、备注。
- 企业沟通中心支持文本聊天。
- 企业沟通中心支持询价表单卡。
- 企业沟通中心支持议价表单卡。
- 卖家接收询价/议价。
- 卖家接受、拒绝、修改议价方案。
- 卖家在议价中提出可协商指标参数。
- 买家确认或拒绝卖家修改方案。
- 议价状态流转：草稿、待卖家响应、卖家已修改、待买家确认、议价成功、已拒绝、已撤回、已失效、已转订单。
- 议价成功后卖家发起订单成交入口。
- 沟通记录、表单快照、状态日志可追溯。

### 14.2 MVP 不做

- 不做完整订单状态机。
- 不做合同完整流程。
- 不做物流履约流程。
- 不做金融授信流程。
- 不做自动锁定库存。
- 不做自动成交。
- 不做 AI 自动替买家议价。
- 不做 AI 自动替卖家接受或拒绝。
- 不做跨多个指标商品的组合议价。
- 不做复杂审批流。

---

## 15. 协议结论

买家议价沟通场景的核心不是普通聊天，而是围绕指标商品形成结构化询价、结构化议价和可追溯交易意向。

MVP 阶段应在企业即时聊天中嵌入表单式询价和议价能力，让买家可以从商品列表页或详情页发起诉求，让卖家可以接收、修改、拒绝或接受议价，并在议价成功后由卖家发起订单成交。

议价沟通单可以拥有自身状态流转，但不得直接修改卖家侧指标商品主状态，不得直接修改库存状态，也不得绕过订单业务域完成成交。

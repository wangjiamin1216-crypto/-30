# 平台指标商品审核后台最小闭环协议

---

## 1. 后台定位

本后台是支撑「卖家指标经营工作台 MVP」的**平台指标商品审核操作端**。

它不是完整运营后台，不承载完整平台运营、用户管理、权限管理、财务、物流、合同、数据大盘、风控中心或指标研究院能力。

当前后台只围绕一个业务对象展开：**指标商品**。

后台核心职责是：

- 查看卖家提交的待审核指标商品。
- 核对指标商品的基础信息、指标信息、库存/吨位信息、经营信息、图片和附件。
- 对待审核指标商品执行审核通过或审核驳回。
- 审核通过后，使指标商品从「待审核」进入「已上架」。
- 审核驳回后，记录驳回原因和审核意见，使卖家可修改后重新提交。
- 记录审核日志和关键状态流转日志。
- 在必要时支持平台强制下架已上架指标商品。

定位原则：

- 指标优先于商品名称。
- 指标完整性优先于图片展示。
- 审核行为必须服从指标商品状态机。
- 审核意见、驳回原因和强制下架原因必须可追踪、可回溯。
- 后台只做最小审核闭环，不扩展完整运营后台。

---

## 2. 使用角色

当前 MVP 只定义以下 2 类平台侧角色：

| 角色 | 角色说明 | 可查看待审核商品 | 可审核 | 可强制下架 | 可查看审核日志 |
| --- | --- | --- | --- | --- | --- |
| 平台审核人员 | 负责处理卖家提交的指标商品审核 | 是 | 是 | 否 | 是，仅查看自己可处理范围内的审核日志 |
| 平台管理员 | 负责审核管理、异常处理和平台侧兜底操作 | 是 | 是 | 是 | 是，可查看全部审核日志和强制下架日志 |

### 2.1 谁可以审核

- 平台审核人员可以对「待审核」状态的指标商品执行审核通过或审核驳回。
- 平台管理员可以对「待审核」状态的指标商品执行审核通过或审核驳回。
- 任何角色都不得绕过「待审核」状态直接将草稿、审核驳回或已下架商品置为已上架。

### 2.2 谁可以查看

- 平台审核人员可以查看待审核指标商品列表、审核详情和必要的附件/图片预览。
- 平台管理员可以查看全部指标商品审核相关信息，包括待审核、审核驳回、已上架、已下架商品的审核追溯信息。

### 2.3 谁可以强制下架

- 仅平台管理员可以对「已上架」指标商品执行强制下架。
- 平台审核人员不具备强制下架权限。
- 强制下架必须填写下架原因，并记录状态日志。

### 2.4 谁可以查看审核日志

- 平台审核人员可以查看其审核范围内的审核日志。
- 平台管理员可以查看全部审核日志、驳回日志、通过日志和强制下架日志。
- 审核日志只能追加，不允许删除或覆盖。

## 3. 页面范围

当前后台只包含以下页面和能力：

1. 待审核指标商品列表。
2. 指标商品审核详情。
3. 审核通过操作。
4. 审核驳回操作。
5. 审核日志查看。
6. 必要的附件/图片预览。

说明：

- 列表页用于快速定位待审核指标商品。
- 详情页用于完成指标、库存、吨位、附件和卖家信息核对。
- 审核通过和审核驳回是当前后台的核心操作。
- 审核日志用于追溯平台审核行为和状态变化。
- 附件/图片预览只服务审核判断，不扩展为完整素材管理。

当前页面范围不包含：

- 用户管理。
- 权限管理中心。
- 财务管理。
- 物流管理。
- 合同管理。
- 数据大盘。
- 风控中心。
- 研究院。
- 完整运营后台。

## 4. 审核列表页

### 4.1 页面目标

审核列表页用于让平台人员快速查看、筛选和进入卖家提交的待审核指标商品。

页面目标：

- 聚合当前待处理的指标商品审核任务。
- 突出指标商品的核心指标、卖家企业、库存/可售吨位和提交时间。
- 支持平台人员进入审核详情并完成审核处理。
- 支持平台管理员追踪异常状态和审核处理进度。

### 4.2 筛选条件

当前 MVP 支持以下筛选条件：

| 筛选条件 | 说明 |
| --- | --- |
| 当前状态 | 默认筛选「待审核」，可扩展查看审核驳回、已上架、已下架 |
| 商品分类 | 按指标商品所属品类筛选 |
| 卖家企业 | 按卖家企业名称或企业 ID 搜索 |
| 指标商品名称 | 按商品名称关键词搜索 |
| 核心指标 | 按核心指标名称或指标值关键词搜索 |
| 提交时间 | 按最近一次提交审核时间筛选 |
| 审核人 | 平台管理员可按审核人筛选历史审核记录 |

说明：

- 默认视图应优先展示「待审核」指标商品。
- 当前 MVP 不做复杂高级筛选器，不做数据大盘式统计分析。

### 4.3 列表字段

列表字段至少包含：

| 字段 | 字段说明 | 来源 |
| --- | --- | --- |
| 指标商品名称 | 商品载体名称，用于辅助识别 | 基础字段 |
| 卖家企业 | 提交该指标商品的卖家企业 | 基础字段 |
| 商品分类 | 指标商品所属品类 | 基础字段 |
| 核心指标摘要 | 核心指标名称、指标值、指标单位和必要容差摘要 | 指标字段 |
| 库存 / 可售吨位 | 当前库存数量和可售吨位 | 经营字段 |
| 提交时间 | 最近一次提交审核时间 | 状态字段 |
| 当前状态 | 草稿、待审核、审核驳回、已上架、已下架中的当前状态 | 状态字段 |
| 操作入口 | 查看详情、审核、查看日志等入口 | 页面操作 |

可弱化展示字段：

- 指标商品 ID。
- 卖家企业 ID。
- 状态版本号。
- 最近修改时间。

### 4.4 操作按钮

列表页允许的操作按钮：

| 当前状态 | 平台审核人员按钮 | 平台管理员按钮 |
| --- | --- | --- |
| 待审核 | 查看详情、审核 | 查看详情、审核、查看日志 |
| 审核驳回 | 查看详情、查看日志 | 查看详情、查看日志 |
| 已上架 | 查看详情、查看日志 | 查看详情、查看日志、强制下架 |
| 已下架 | 查看详情、查看日志 | 查看详情、查看日志 |

按钮规则：

- 「审核」只允许在当前状态为「待审核」时出现或可执行。
- 「强制下架」只允许平台管理员对「已上架」指标商品执行。
- 所有操作必须以服务端最新状态为准。
- 如果列表页状态与服务端最新状态不一致，操作必须被拒绝并提示刷新。

### 4.5 空状态

待审核列表为空时，应展示：

- 当前没有待审核指标商品。
- 可切换查看历史审核记录。
- 不生成虚假审核任务。

筛选结果为空时，应展示：

- 未找到符合条件的指标商品。
- 支持清空筛选条件后重新查看。

### 4.6 异常状态

列表页需要识别并提示以下异常：

| 异常状态 | 触发条件 | 处理规则 |
| --- | --- | --- |
| 审核超时 | 待审核商品超过平台承诺审核时限 | 显示超时提醒，允许平台人员优先处理 |
| 数据缺失 | 待审核版本关键字段缺失 | 标记为资料异常，进入详情后展示缺失项 |
| 附件不可预览 | 图片或附件加载失败 | 提示附件异常，不阻断进入详情 |
| 状态冲突 | 列表状态与服务端最新状态不一致 | 拒绝旧状态操作并提示刷新 |
| 权限异常 | 当前角色无权执行按钮动作 | 禁用动作或拒绝操作并记录异常日志 |

异常处理原则：

- 异常标签不新增指标商品主状态。
- 异常不得绕过审核状态机。
- 异常操作必须记录异常日志。

## 5. 审核详情页

审核详情页用于平台人员完成指标商品审核判断，是当前后台的核心页面。

### 5.1 页面结构

审核详情页包含以下区域：

1. 基础信息。
2. 指标信息。
3. 库存 / 吨位信息。
4. 图片 / 附件。
5. 卖家信息。
6. 历史修改记录。
7. 审核日志。
8. 审核操作区。

### 5.2 基础信息

基础信息用于识别指标商品及其审核版本。

展示字段：

- 指标商品 ID。
- 商品名称。
- 商品品类。
- 商品说明。
- 当前状态。
- 状态版本号。
- 创建时间。
- 最近修改时间。
- 提交审核时间。
- 提交审核人。

规则：

- 待审核详情页展示的是卖家提交审核时的待审核版本。
- 审核期间不得无记录修改待审核版本。
- 当前状态必须以服务端最新状态为准。

### 5.3 指标信息

指标信息是审核详情页的核心审核内容。

展示字段：

- 指标组。
- 核心指标标记。
- 指标名称。
- 指标值。
- 指标单位。
- 指标容差下限。
- 指标容差上限。
- 指标说明。
- 指标排序。

审核重点：

- 是否至少存在一个核心指标。
- 指标名称、指标值、指标单位是否完整。
- 指标容差是否合理。
- 指标说明是否与指标值、指标单位冲突。
- 指标内容是否符合平台经营规则和品类要求。

### 5.4 库存 / 吨位信息

库存 / 吨位信息用于判断指标商品是否具备基础经营能力。

展示字段：

- 库存数量。
- 可售吨位。
- 最小起售数量。
- 库存预警阈值。
- 库存预警标签。
- 报价方式。
- 报价金额。
- 价格单位。
- 价格有效期。
- 生产区域。
- 交付区域。
- 交易方式。
- 交付方式。
- 经营备注。

审核重点：

- 库存数量和可售吨位是否为空或小于 0。
- 可售吨位是否大于库存数量。
- 最小起售数量是否大于可售吨位。
- 报价方式、价格单位、交付区域、交易方式、交付方式是否完整。
- 价格有效期是否已经失效。
- 经营信息是否与指标商品的实际经营能力冲突。

### 5.5 图片 / 附件

图片 / 附件用于辅助审核，不高于指标信息优先级。

展示内容：

- 商品图片预览。
- 规格书。
- 检测报告。
- 资质材料。
- 其他卖家上传的审核辅助材料。

规则：

- 附件如作为当前品类审核必要材料，则缺失时应驳回。
- 图片或附件无法预览时，应提示附件异常。
- 附件预览只服务审核判断，不扩展为完整素材管理、文件中心或证照管理系统。

### 5.6 卖家信息

卖家信息用于辅助判断指标商品归属和基础经营主体。

展示字段：

- 卖家企业 ID。
- 卖家企业名称。
- 企业基础状态摘要。
- 提交审核人。
- 最近修改人。

说明：

- 当前 MVP 只展示审核所需的卖家摘要信息。
- 不展开完整企业档案、用户管理、权限管理或资质中心。

### 5.7 历史修改记录

历史修改记录用于追溯卖家在提交前或驳回后对指标商品的关键修改。

展示内容：

- 修改人。
- 修改时间。
- 修改字段摘要。
- 修改前内容摘要。
- 修改后内容摘要。
- 对应状态版本号。

规则：

- 影响审核主版本的字段修改必须可追溯。
- 历史修改记录不得被删除。
- 当前 MVP 不做复杂字段 diff 可视化，只保留必要摘要。

### 5.8 审核日志

审核日志用于展示该指标商品的审核和状态流转记录。

展示内容：

- 审核人。
- 审核时间。
- 操作类型。
- 原状态。
- 新状态。
- 审核意见。
- 驳回原因。
- 关联指标商品 ID。

规则：

- 审核日志按时间倒序展示。
- 审核意见和驳回原因不得覆盖，只能追加。
- 平台强制下架日志也应在此处可追溯。

### 5.9 审核操作区

审核操作区用于平台人员执行当前状态允许的审核动作。

待审核状态下允许：

- 审核通过。
- 审核驳回。

已上架状态下，平台管理员允许：

- 强制下架。

审核操作区字段：

- 审核结论。
- 审核意见。
- 驳回原因。
- 强制下架原因。

规则：

- 审核通过时，审核意见可填写，当前 MVP 不强制必填。
- 审核驳回时，驳回原因和审核意见必须填写。
- 平台强制下架时，下架原因必须填写。
- 操作提交前必须校验当前状态和状态版本号。

## 6. 审核操作规则

### 6.1 审核通过条件

指标商品从「待审核」进入「已上架」必须满足：

- 当前状态为「待审核」。
- 待审核版本存在且未被撤回。
- 指标商品基础信息完整。
- 至少存在一个核心指标。
- 指标名称、指标值、指标单位完整。
- 指标容差和指标说明不存在明显冲突。
- 库存数量、可售吨位、报价方式、价格单位、交付区域、交易方式、交付方式等必要经营字段完整。
- 可售吨位、库存数量、报价金额等数值字段符合校验规则。
- 必要图片、附件或资质材料已上传且可用于审核判断。
- 卖家企业基础状态不阻断当前指标商品上架。
- 不存在平台要求必须阻断上架的异常。

### 6.2 审核驳回条件

出现以下情况时，平台人员可以或必须驳回：

- 基础信息缺失或明显错误。
- 核心指标缺失。
- 指标名称、指标值、指标单位不完整。
- 指标容差不合理或与指标值冲突。
- 指标说明与指标内容明显冲突。
- 库存数量、可售吨位、最小起售数量等经营信息不符合校验规则。
- 报价方式、报价金额、价格单位或价格有效期不符合平台要求。
- 生产区域、交付区域、交易方式、交付方式缺失或不合理。
- 必要附件、检测报告、资质材料缺失或无法支撑审核判断。
- 商品信息、指标信息或经营信息存在明显虚假、矛盾或不可经营风险。

### 6.3 驳回原因是否必填

- 审核驳回时，驳回原因必须填写。
- 审核驳回时，审核意见必须填写。
- 如存在多项驳回原因，应记录主要驳回原因，并在审核意见中补充说明。
- 驳回原因和审核意见必须对卖家可见，用于指导卖家修改后重新提交。

### 6.3.1 审核驳回原因枚举

当前 MVP 支持以下驳回原因枚举：

| 驳回原因 | 说明 |
| --- | --- |
| 基础信息缺失 | 商品名称、商品品类、商品说明等基础信息缺失或不完整 |
| 核心指标缺失 | 未设置核心指标，或核心指标不足以支撑指标商品经营判断 |
| 指标信息异常 | 指标名称、指标值、指标单位、指标容差不完整或不合理 |
| 指标说明不清晰 | 指标口径、检测口径或适用条件描述不足 |
| 库存/吨位异常 | 库存数量、可售吨位、最小起售数量不合法或相互冲突 |
| 报价信息异常 | 报价方式、报价金额、价格单位或价格有效期异常 |
| 交付信息异常 | 生产区域、交付区域、交易方式或交付方式不完整或不合理 |
| 图片不合规 | 图片缺失、模糊、格式错误、无法预览或与商品不符 |
| 附件缺失 | 检测报告、资质材料、规格书等必要附件缺失 |
| 附件不合规 | 附件无法预览、内容不符、材料无效或格式不符合要求 |
| 企业资质异常 | 卖家企业状态、资质或经营权限不满足发布要求 |
| 信息疑似不真实 | 商品信息、指标信息或经营信息存在明显虚假、矛盾或不可经营风险 |
| 其他 | 不属于上述原因时使用，必须填写补充审核意见 |

规则：

- 审核驳回时必须至少选择一个驳回原因。
- 支持选择多个驳回原因。
- 如选择“其他”，审核意见必须说明具体问题。
- 驳回原因不得覆盖历史记录，只能追加到本次审核日志。

### 6.4 审核通过后状态变化

审核通过后：

- 原状态：待审核。
- 新状态：已上架。
- 审核结果：审核通过。
- 指标商品正式对买家可见。
- 买家可以查看该指标商品并发起询价、议价。
- 系统生成审核通过日志和状态流转日志。

### 6.5 审核驳回后状态变化

审核驳回后：

- 原状态：待审核。
- 新状态：审核驳回。
- 审核结果：审核不通过。
- 指标商品仍不可被买家查看。
- 买家不可发起询价、议价。
- 卖家可以查看驳回原因和审核意见。
- 卖家可修改后重新提交审核。
- 系统生成审核驳回日志和状态流转日志。

### 6.6 是否允许二次审核

允许二次审核，但必须通过状态机重新进入「待审核」。

规则：

- 「审核驳回」状态下，卖家修改后可重新提交，状态从「审核驳回」进入「待审核」。
- 平台人员只能审核当前最新待审核版本。
- 历史驳回原因、审核意见和审核日志不得覆盖。
- 每次重新提交必须生成新的状态版本号。
- 每次二次审核必须生成新的审核日志。

### 6.7 是否允许平台强制下架

允许平台强制下架，但仅限平台管理员执行。

规则：

- 仅「已上架」状态允许平台强制下架。
- 强制下架后，状态从「已上架」进入「已下架」。
- 平台管理员必须填写强制下架原因。
- 强制下架不得删除历史沟通、历史订单、历史合同或历史经营记录。
- 强制下架必须生成状态日志。

## 7. 与卖家端状态机关系

本后台必须严格服从《卖家指标商品经营状态机协议》。

当前后台参与的状态流转只包含：

| 触发方 | 操作 | 原状态 | 新状态 | 说明 |
| --- | --- | --- | --- | --- |
| 平台审核人员 / 平台管理员 | 审核通过 | 待审核 | 已上架 | 指标商品通过审核后正式进入经营状态 |
| 平台审核人员 / 平台管理员 | 审核驳回 | 待审核 | 审核驳回 | 指标商品审核不通过，卖家需修改 |
| 卖家 | 重新提交 | 审核驳回 | 待审核 | 卖家根据驳回原因修改后重新提交 |
| 平台管理员 | 平台强制下架 | 已上架 | 已下架 | 平台因异常、违规或规则原因停止商品经营 |

必须明确：

- 审核通过：待审核 → 已上架。
- 审核驳回：待审核 → 审核驳回。
- 卖家重新提交：审核驳回 → 待审核。
- 平台强制下架：已上架 → 已下架。

禁止流转：

- 草稿 → 已上架。
- 审核驳回 → 已上架。
- 已下架 → 已上架。
- 待审核 → 已下架，除非先完成审核驳回或由状态机另行定义。
- 任意状态绕过日志直接修改为已上架。

说明：

- 卖家端负责创建、编辑、提交审核、查看驳回原因、重新提交和主动下架。
- 平台后台负责审核通过、审核驳回、查看审核日志和平台强制下架。
- 双端必须共享同一指标商品状态机和状态版本号。

## 8. 审核日志要求

每次审核操作必须记录审核日志。

审核日志必须包含：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 审核人 | 是 | 执行审核动作的平台人员 |
| 审核时间 | 是 | 审核动作提交时间 |
| 操作类型 | 是 | 审核通过、审核驳回、强制下架等 |
| 原状态 | 是 | 操作前指标商品状态 |
| 新状态 | 是 | 操作后指标商品状态 |
| 审核意见 | 是 | 审核说明；驳回时必须对卖家形成明确修改指引 |
| 驳回原因 | 条件必填 | 审核驳回时必填；审核通过时可为空 |
| 关联指标商品 ID | 是 | 被审核的指标商品唯一标识 |

建议同时记录：

- 操作人角色。
- 卖家企业 ID。
- 状态版本号。
- 提交审核时间。
- 审核结果。
- 强制下架原因。
- 触发来源：平台审核、平台管理员、系统规则。
- 备注。

日志规则：

- 审核日志只能追加，不允许删除。
- 审核意见、驳回原因、强制下架原因不得覆盖。
- 每次状态变化必须有对应状态日志。
- 非法流转、权限异常、并发冲突也应记录异常日志。
- 日志应支持按指标商品 ID 追溯完整审核生命周期。

不同操作的日志要求：

| 操作类型 | 必填日志信息 |
| --- | --- |
| 审核通过 | 审核人、审核时间、操作类型、原状态、新状态、审核意见、关联指标商品 ID |
| 审核驳回 | 审核人、审核时间、操作类型、原状态、新状态、审核意见、驳回原因、关联指标商品 ID |
| 平台强制下架 | 操作人、操作时间、操作类型、原状态、新状态、强制下架原因、关联指标商品 ID |

### 8.1 审核日志数据结构

审核日志建议至少包含：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 审核日志 ID | 是 | 审核日志唯一标识 |
| 指标商品 ID | 是 | 被审核的指标商品 |
| 卖家企业 ID | 是 | 指标商品所属卖家企业 |
| 审核人 ID | 是 | 执行审核动作的平台人员 |
| 审核人名称 | 否 | 审核人展示名称 |
| 审核人角色 | 是 | 平台审核人员或平台管理员 |
| 审核时间 | 是 | 审核操作提交时间 |
| 审核结果 | 是 | 审核通过或审核驳回 |
| 操作类型 | 是 | 审核通过、审核驳回、强制下架 |
| 原状态 | 是 | 操作前状态 |
| 新状态 | 是 | 操作后状态 |
| 驳回原因 | 条件必填 | 审核驳回时必填 |
| 审核意见 | 条件必填 | 审核驳回时必填，审核通过时可选 |
| 强制下架原因 | 条件必填 | 平台强制下架时必填 |
| 待审核版本号 | 条件必填 | 审核待审核商品时必填 |
| 状态版本号 | 是 | 操作后的最新状态版本号 |
| 触发来源 | 是 | 平台审核、平台管理员或系统规则 |
| 备注 | 否 | 补充说明 |

### 8.2 审核日志规则

- 审核日志只能追加，不允许删除或覆盖。
- 审核意见、驳回原因、强制下架原因必须可追溯。
- 审核通过、审核驳回和强制下架必须同时生成状态日志。
- 如果审核操作因状态冲突、权限异常或版本号不一致失败，应记录异常日志。
- 平台人员只能审核服务端最新待审核版本。

## 9. 当前 MVP 不做

当前 MVP 明确不做：

- 多级审核。
- 自动审核。
- 复杂风控。
- 审核工作流配置。
- 批量审核。
- 审核权限中心。
- 完整运营后台。
- 用户管理。
- 权限管理中心。
- 财务管理。
- 物流管理。
- 合同管理。
- 数据大盘。
- 风控中心。
- 指标研究院。
- 完整企业资质中心。
- 完整证照管理。
- 完整文件素材管理。
- 完整订单、合同、履约、售后流程。

边界说明：

- 当前后台只服务指标商品审核最小闭环。
- 当前后台只处理指标商品状态机中平台侧必须参与的流转。
- 当前后台不定义新的指标商品主状态。
- 当前后台不替代卖家指标经营工作台。
- 当前后台不扩展完整平台运营后台。
